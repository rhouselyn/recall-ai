## 哔哩哔哩

- **本人和收藏夹。** 社区记录的 Web 接口 `GET /x/web-interface/nav` 用会话 `SESSDATA` 返回 `isLogin` 与本人 `mid`。用该 `mid` 请求 `GET /x/v3/fav/folder/created/list-all?up_mid=<mid>`，取 `data.list[].id` 作为完整夹 ID。`fid` 是原始 ID。接口记录把 `attr` 的最低位标为私密，需用已知公开夹和私密夹对照。关注或收藏的夹、合集对应另一个 `GET /x/v3/fav/folder/collected/list`，按独立范围处理。 [登录信息接口记录](https://github.com/bilibili-plugins/bilibili-api-collect/blob/cfc5fddcc8a94b74d91970bb5b4eaeb349addc47/docs/login/login_info.md) · [收藏夹接口记录](https://github.com/bilibili-plugins/bilibili-api-collect/blob/cfc5fddcc8a94b74d91970bb5b4eaeb349addc47/docs/fav/info.md)
- **夹内分页。** `GET /x/v3/fav/resource/list` 传 `media_id=<完整夹 ID>`、`pn`、`ps=20`、`platform=web`，读取 `data.medias` 并以 `data.has_more` 判断是否继续。社区接口记录明确要求用相应账号登录查看有权限限制的夹，并列出 `-403`。保留 `fav_time`、内容类型和稳定 ID。`null`、失效视频与真正空夹分开处理。 [条目接口记录](https://github.com/bilibili-plugins/bilibili-api-collect/blob/cfc5fddcc8a94b74d91970bb5b4eaeb349addc47/docs/fav/list.md)
- **依赖与 RSS。** `Nemo2011/bilibili-api` 于 2026-07-06 归档，当前主分支只有关停声明。社区接口记录的原上游 `SocialSisterYi/bilibili-API-collect` 也已关停。可以用固定版本定位候选请求，项目不依赖该停维护 SDK。RSSHub `/bilibili/fav/:uid/:fid/:embed?` 会用 `BILIBILI_COOKIE_<uid>` 请求指定夹，单次取 20 条。`/bilibili/user/fav/:uid/:embed?` 仍使用旧 `/x/v2/fav/video`，固定第一页 30 条。两者都要用本人的私密夹验证，适合作为最近窗口。 [SDK 关停声明](https://github.com/Nemo2011/bilibili-api/blob/3798d3b3bd3c3a93678d5a0367637a19262303ef/README.md) · [接口记录上游关停声明](https://github.com/SocialSisterYi/bilibili-API-collect/blob/deprecated/README.md) · [RSSHub 指定夹](https://github.com/DIYgod/RSSHub/blob/89956595df9a690fe1101d727ce4b04ff4a7064f/lib/routes/bilibili/fav.ts) · [RSSHub 默认夹](https://github.com/DIYgod/RSSHub/blob/89956595df9a690fe1101d727ce4b04ff4a7064f/lib/routes/bilibili/user-fav.ts) · [RSSHub 配置](https://github.com/DIYgod/RSSHub/blob/89956595df9a690fe1101d727ce4b04ff4a7064f/lib/config.ts)

## 抖音

- **收藏视频与分组。** `TikTokDownloader` 的 `Collection` 用登录会话请求 `POST /aweme/v1/web/aweme/listcollection/`，提交 `count`、`cursor`，消费 `aweme_list`、`cursor`、`has_more`。收藏夹列表 `GET /aweme/v1/web/collects/list/` 读取 `collects_list`，夹内条目 `GET /aweme/v1/web/collects/video/list/` 另传 `collects_id`，两者也使用游标。收藏合集、音乐和短剧各有单独端点。按 `aweme_id` 归并内容并保留分组关系。`/aweme/v1/web/aweme/favorite/` 对应喜欢。 [收藏视频源码](https://github.com/JoeanAmier/TikTokDownloader/blob/f766a6eff25b76fe4d737f10c27258e4da65df7d/src/interface/collection.py) · [分组源码](https://github.com/JoeanAmier/TikTokDownloader/blob/f766a6eff25b76fe4d737f10c27258e4da65df7d/src/interface/collects.py) · [RSSHub 收藏与喜欢的端点分流](https://github.com/DIYgod/RSSHub/blob/89956595df9a690fe1101d727ce4b04ff4a7064f/lib/routes/douyin/saved-posts.ts)
- **已知失败。** `jiji262/douyin-downloader` 的 CLI 维护说明记录，自 2026 年 8 月起，收藏、收藏夹和喜欢相关的非页面请求会被 Argus 拒绝并返回 403。项目的桌面端在登录页面上下文发请求，开源 CLI 的收藏路径仍受该限制。`TikTokDownloader` 也有同类报告。此处的端点可以用来识别正常页面返回，直接用 Cookie 重放须单独验收。 [CLI 维护说明](https://github.com/jiji262/douyin-downloader/blob/7c4b8b2252acbfe24728664cc77364bb75a24ecb/AGENTS.md) · [CLI 当前限制](https://github.com/jiji262/douyin-downloader/blob/7c4b8b2252acbfe24728664cc77364bb75a24ecb/README.md) · [收藏读取故障记录](https://github.com/JoeanAmier/TikTokDownloader/issues/785)
- **本人 RSS。** `/douyin/collection` 要求实例设置 `DOUYIN_COOKIE`。RSSHub 用 Playwright 打开 `/user/self`，进入「收藏 → 视频」，监听平台页面发出的 `listcollection` 首个响应。首屏不含分组、音乐、合集或短剧，`pubDate` 取视频创作时间。空列表会报错。`/douyin/likes/:uid` 是另一个路由，`self` 对应配置账号的点赞列表。 [收藏路由](https://github.com/DIYgod/RSSHub/blob/89956595df9a690fe1101d727ce4b04ff4a7064f/lib/routes/douyin/collection.ts) · [共用读取处理器](https://github.com/DIYgod/RSSHub/blob/89956595df9a690fe1101d727ce4b04ff4a7064f/lib/routes/douyin/saved-posts.ts) · [喜欢路由](https://github.com/DIYgod/RSSHub/blob/89956595df9a690fe1101d727ce4b04ff4a7064f/lib/routes/douyin/likes.ts)

## 知乎

- **本人私密夹和已知夹 ID。** 官方 Access Secret 的收藏夹枚举和夹内容接口公开约定覆盖公开范围。`handsomestWei/zhihu-fetch-skill` 的网页路径是 `/api/v4/members/{slug}/favlists` 枚举公开夹，以及 `/api/v4/collections/{id}/items?offset=<n>&limit=20` 读取指定夹。后者可带登录会话，另有独立持久化浏览器内请求的后备路径，依据 `paging.is_end` 续页。该工具的主页枚举只声明公开，条目归一化偏向文章和回答。先从本人登录页面核验私密夹发现，再用已知私密夹 ID 验证分页与类型覆盖。 [官方收藏夹列表](https://developer.zhihu.com/docs?key=user_favlists) · [官方夹内容](https://developer.zhihu.com/docs?key=favlist_contents) · [第三方读取源码](https://github.com/handsomestWei/zhihu-fetch-skill/blob/4d1f999e09156c9332aef88143c1327b5b99cbf8/scripts/zhihu_fetch/fetch/collection.py)
- **RSS。** `/zhihu/collection/:id/:getAll?` 默认取 20 条。条目请求会发送 `ZHIHU_COOKIES`，随后读夹标题和简介的 HTML 请求没有显式传该会话。`getAll` 用 `Math.round(totals / 20)` 算页数，例如 `21` 条只算一页。后续页缓存键以请求 URL 为基础。Feed 的 `pubDate` 对普通条目来自内容更新时间。以此作为指定夹候选窗口，私密元数据和同步完成状态由本人账号实验单独核实。 [RSSHub 路由源码](https://github.com/DIYgod/RSSHub/blob/89956595df9a690fe1101d727ce4b04ff4a7064f/lib/routes/zhihu/collection.ts)

## 私密订阅和上线门槛

- RSSHub 的上游会话保存在实例配置，订阅请求走另一层访问控制。没有设置 `ACCESS_KEY` 时，代码默认允许请求。有设置时，普通订阅使用 URL 的 `key` 或基于路径计算的 `code`，持有该 URL 的人可访问对应内容。抖音处理器按账号会话摘要区分该路由的缓存，知乎分页缓存按上游 URL 区分。本人私密订阅限定为本地或带鉴权的单用户实例，缓存、订阅链接、日志和阅读器都按私密数据处理。 [访问控制](https://github.com/DIYgod/RSSHub/blob/89956595df9a690fe1101d727ce4b04ff4a7064f/lib/middleware/access-control.ts) · [访问凭据校验](https://github.com/DIYgod/RSSHub/blob/89956595df9a690fe1101d727ce4b04ff4a7064f/lib/utils/weibo-oauth.ts) · [抖音缓存](https://github.com/DIYgod/RSSHub/blob/89956595df9a690fe1101d727ce4b04ff4a7064f/lib/routes/douyin/saved-posts.ts) · [知乎缓存](https://github.com/DIYgod/RSSHub/blob/89956595df9a690fe1101d727ce4b04ff4a7064f/lib/routes/zhihu/collection.ts)
- 联调时在本人账号用已知公开夹、私密夹、空夹和超过一页的夹做对照，核验登录身份、夹 ID、重复条目和最后一页，再分别模拟失效会话、限流和中途失败。空响应只有在身份、响应结构和结束条件均通过时才算成功空列表。首屏和有预算的采集标为窗口或子集，保留旧记录。只有完成已声明范围的枚举并明确到达各列表末尾，才允许用快照移除缺席的收藏关系。收藏时间按原字段记录，未返回时留空。
# 2026-11-11 视频平台补充调查与实现

- **B 站**：社区记录的已登录接口通过 `nav` 确认本人 UID，用 `folder/created/list-all` 列举本人创建的收藏夹（包括私密夹），再用 `resource/list` 分页读取。当前实现走本机登录页面会话，分页请求达到预算时保存进度，下次继续，不把部分结果当作完整快照删除旧数据。已实测本人账号成功写入；订阅的他人收藏夹不属于此接口范围。 [收藏夹接口](https://github.com/bilibili-plugins/bilibili-api-collect/blob/master/docs/fav/info.md) · [内容接口](https://github.com/bilibili-plugins/bilibili-api-collect/blob/master/docs/fav/list.md)
- **抖音**：RSSHub 的开源方案通过已登录浏览器打开本人页面，选择收藏及视频，观察页面自身发出的 `listcollection` 响应；本项目采用相同路线。直接调用非官方接口可能因签名、风控和页面改版失效，分组及完整覆盖仍需真人账号验证。 [RSSHub 实现](https://github.com/DIYgod/RSSHub/blob/89956595df9a690fe1101d727ce4b04ff4a7064f/lib/routes/douyin/saved-posts.ts) · [第三方工具的限制](https://github.com/jiji262/douyin-downloader)
- **YouTube 官方 API**：OAuth 后 `playlists.list(mine=true)` 可列出本人创建的播放列表，`playlistItems.list` 可读取有权限的列表；`videos.list(myRating=like)` 的点赞列表最多 1000 条。官方接口明确不支持读取稍后观看，因此本项目改用本机登录会话与开源 yt-dlp。 [官方播放列表指南](https://developers.google.com/youtube/data/guides/implementation/playlists) · [playlistItems.list](https://developers.google.com/youtube/data/reference/rest/v3/playlistItems/list) · [videos.list](https://developers.google.com/youtube/data/reference/rest/v3/videos/list) · [yt-dlp](https://github.com/yt-dlp/yt-dlp)
- **YouTube 实际覆盖**：优先尝试 `WL`（稍后观看）、`LL`（喜欢的视频）和登录页面滚动发现的播放列表；各列表权限独立、部分失败不会删除原数据。发现范围不保证完整，也不保证第三方方式长期可用。凭据在隔离浏览器中保存，读取时只在内存中交给 yt-dlp；自动刷新依赖本机服务运行和有效登录。尚需实际 Google 账号与网络验证。
